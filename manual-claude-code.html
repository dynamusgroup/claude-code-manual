01 — Instalação & Setup Inicial

Configure o Claude Code do zero em minutos

Instalar via npm (recomendado)

# Instalar globalmente
npm install -g @anthropic-ai/claude-code

# Verificar versão instalada
claude --version

# Iniciar Claude Code
claude

Primeiro acesso

# Abrir em um projeto existente
cd meu-projeto
claude

# Inicializar memória do projeto
claude /init

# Verificar configuração atual
claude /config

🍎 macOS

Requer Node.js 18+. Use brew install node ou baixe em nodejs.org.

🐧 Linux

Use nvm para gerenciar versões do Node. Recomendado Node 20 LTS.

🪟 Windows

Use WSL2 (Ubuntu) para melhor compatibilidade. Claude Code funciona nativamente no terminal WSL.

02 — Arquivos Importantes

Os arquivos que o Claude Code lê e respeita automaticamente

Obrigatório

CLAUDE.md

O arquivo mais importante. Funciona como um "briefing" que o Claude lê em toda conversa. Coloque regras do projeto, contexto e preferências aqui.

# Localizações possíveis:
./CLAUDE.md          # raiz do projeto
./.claude/CLAUDE.md  # pasta .claude
~/.claude/CLAUDE.md  # global (todo projeto)
Configuração

settings.json

Controla permissões, hooks, variáveis de ambiente e comportamentos automáticos do Claude Code.

# Localizações:
.claude/settings.json        # projeto
~/.claude/settings.json      # global
.claude/settings.local.json  # local (não commitar)
Memória

MEMORY.md

Índice do sistema de memória persistente. O Claude salva aprendizados entre sessões aqui. Gerado automaticamente em ~/.claude/projects/.

Ignorar

.gitignore / .claudeignore

O Claude respeita o .gitignore. Use .claudeignore para esconder arquivos adicionais do contexto do Claude sem afetar o git.

✅

Hierarquia de leitura do CLAUDE.md

O Claude lê primeiro o global (~/.claude/CLAUDE.md), depois o do projeto raiz, depois os de subpastas. Regras mais específicas sobrepõem as gerais.

03 — Organização de Pastas

Estrutura recomendada para projetos com Claude Code

Estrutura recomendada do projeto

meu-projeto/ ├── CLAUDE.md # instruções do projeto ├── .claude/ │ ├── settings.json # configurações │ ├── settings.local.json # segredos locais │ └── commands/ # comandos customizados │ └── deploy.md ├── src/ # código-fonte ├── tests/ # testes ├── docs/ # documentação ├── .env.example # exemplo de variáveis ├── .gitignore └── README.md

Pasta .claude global (usuário)

~/.claude/ ├── CLAUDE.md # regras globais ├── settings.json # config global ├── keybindings.json # atalhos de teclado ├── commands/ # slash commands globais │ └── meu-comando.md └── projects/ # memória por projeto └── meu-projeto/ ├── MEMORY.md # índice de memórias └── memory/ ├── user_role.md └── feedback_tests.md
⚠️

Nunca commite settings.local.json

Adicione .claude/settings.local.json e .env ao .gitignore. Esses arquivos podem conter tokens e chaves de API.

04 — Comandos Essenciais

Slash commands e atalhos mais usados no dia a dia

Comandos embutidos — digite dentro do Claude Code

Comando O que faz Nível
/init Analisa o projeto e cria o CLAUDE.md inicial automaticamente Básico
/config Abre o painel de configurações (tema, modelo, etc.) Básico
/clear Limpa o histórico da conversa atual sem fechar o app Básico
/compact Comprime o contexto para liberar espaço de tokens Médio
/memory Gerencia memórias salvas (ver, editar, remover) Médio
/review Revisão de código das mudanças atuais da branch Médio
/cost Mostra o custo estimado da sessão atual em tokens Médio
/help Lista todos os comandos disponíveis com descrição Básico
/doctor Verifica a saúde da instalação (MCP, permissões, etc.) Avançado
/mcp Lista e gerencia servidores MCP conectados Avançado
/fast Ativa modo rápido (apenas Opus 4.6) — saída mais veloz Especial

Atalhos de teclado no terminal

AtalhoAção
Ctrl + CInterrompe a geração atual
Ctrl + LLimpa a tela (mantém contexto)
↑ / ↓Navega pelo histórico de prompts
Shift + EnterQuebra linha sem enviar o prompt
TabAutocomplete de comandos e caminhos de arquivo
Ctrl + RBusca no histórico de prompts

Flags de linha de comando (terminal)

# Executar um prompt direto sem abrir o modo interativo
claude -p "explique o arquivo src/auth.ts"

# Modo não-interativo (útil em scripts/CI)
claude --no-interactive -p "rode os testes e me diga se há erros"

# Usar um modelo específico
claude --model claude-opus-4-7

# Continuar a última conversa
claude --continue

# Retomar conversa por ID
claude --resume <session-id>

05 — CLAUDE.md na Prática

Como escrever um CLAUDE.md que realmente funciona

Exemplo de CLAUDE.md para projeto web

# Projeto: App de E-commerce

## Stack
- Frontend: Next.js 14 + TypeScript
- Backend: Node.js + Prisma + PostgreSQL
- Testes: Vitest + Playwright

## Regras de Código
- Sempre usar TypeScript strict
- Componentes React com arrow functions
- Nomes de variáveis em camelCase
- Nunca commitar sem rodar os testes

## Comandos úteis
- `npm run dev` — servidor local
- `npm run test` — roda testes
- `npm run db:push` — migração do banco

## Não fazer
- Não usar `any` no TypeScript
- Não instalar libs sem perguntar
- Não modificar arquivos em /legacy

Seções recomendadas

🏗️

Stack & Tecnologias

Liste linguagens, frameworks e versões. O Claude adapta sugestões à sua stack.

📋

Convenções de Código

Padrões de nomenclatura, estilo, lint, formatação. Evita correções desnecessárias.

⚡

Comandos do Projeto

Como rodar, testar, buildar e fazer deploy. O Claude usará esses comandos automaticamente.

🚫

Restrições Explícitas

O que nunca deve ser feito. Arquivos proibidos, libs bloqueadas, ações que precisam de aprovação.

🔐

06 — Permissões & Segurança

Controle o que o Claude pode e não pode fazer

Exemplo de settings.json com permissões

{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff)",
      "Bash(git log *)",
      "Read(**)",
      "Edit(src/**)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force)",
      "Bash(sudo *)",
      "Write(.env)"
    ]
  }
}

Modos de permissão disponíveis

Default

Modo Normal

Claude pede confirmação para ações destrutivas ou ambíguas. Recomendado para iniciantes.

--dangerously-skip-permissions

Bypassa todas as confirmações. Apenas para ambientes isolados e automatizados. Nunca use em produção.

Allowlist

Permissões Granulares

Liste exatamente o que é permitido no settings.json. Melhor equilíbrio entre agilidade e segurança.

🚨

Regras de ouro de segurança

Nunca coloque chaves de API ou senhas no CLAUDE.md. Use variáveis de ambiente. Bloqueie explicitamente rm -rf, git push --force e sudo via deny list.

07 — Como Escrever Prompts Eficientes

A diferença entre um resultado medíocre e um excelente está no prompt

❌

Prompt vago (evite)

"Melhora esse código"

✅

Prompt específico (use)

"Refatore a função getUserData() em src/api/user.ts para usar async/await em vez de callbacks, mantendo a assinatura de tipo atual."

❌

Múltiplas tarefas (evite)

"Cria o login, faz o dashboard, escreve os testes e documenta tudo"

✅

Uma tarefa por vez (use)

"Primeiro: crie o formulário de login em src/components/LoginForm.tsx com validação de e-mail e senha."

📍 Referencie Arquivos

Mencione caminhos exatos: src/utils/auth.ts linha 42. O Claude vai direto ao ponto sem adivinhar.

🎯 Defina o Output

Diga o que espera: "retorne só o código", "explique em 3 bullet points", "mostre antes e depois".

🔄 Itere em Partes

Tarefas grandes: quebre em etapas. Peça a etapa 1, revise, depois peça a etapa 2.

📏 Dê Restrições

"Sem mudar a interface pública", "sem instalar libs novas", "compatível com Node 18".

🧪 Peça Testes

Adicione "e escreva testes unitários" ao final. O Claude cria testes junto com a implementação.

💾 Use Contexto

"Seguindo o padrão que você usou no componente anterior" — o Claude mantém contexto dentro da sessão.

08 — Sistema de Memória Persistente

O Claude aprende suas preferências entre sessões

Tipos de memória

user

Sobre Você

Seu papel, nível de experiência, preferências de linguagem. "Sou dev sênior em Go, iniciante em React."

feedback

Correções & Validações

O que funcionou e o que não funcionou. "Não use mocks no banco — já causou bug em prod."

project

Estado do Projeto

Decisões tomadas, contexto de negócio, prazos. "Feature X pausada até a release de maio."

reference

Referências Externas

Links, boards, sistemas externos. "Bugs no Linear, projeto BACKEND."

Como salvar e acessar memórias

# Pedir para salvar explicitamente
"Lembra que sempre prefiro
arrow functions em componentes React"

# Pedir para esquecer
"Esquece a regra sobre não usar mocks"

# Ver memórias salvas
/memory

# O Claude também salva automaticamente quando:
# - Você corrige uma abordagem dele
# - Você confirma que algo funcionou
# - Você compartilha contexto do projeto
💡

O que NÃO salvar em memória

Padrões de código (vão no CLAUDE.md), histórico de git (use git log), estado temporário da sessão atual.

09 — Erros Comuns de Iniciantes

Aprenda com os erros mais frequentes

❌

Contexto enorme sem /compact

Sessões muito longas degradam a qualidade das respostas. Use /compact quando a conversa ficar longa ou /clear para começar nova tarefa.

❌

CLAUDE.md vazio ou genérico

Sem instruções, o Claude adivinha o contexto. Rode /init para gerar um arquivo inicial e personalize com as regras do seu projeto.

❌

Pedir mudanças sem revisar

O Claude pode editar arquivos errados ou fazer mais do que pedido. Sempre revise com git diff antes de aceitar grandes mudanças.

❌

Commitar .env ou secrets

Nunca coloque chaves reais no CLAUDE.md ou em prompts. Use variáveis de ambiente e adicione arquivos sensíveis ao .gitignore.

❌

Ignorar os avisos de permissão

Quando o Claude pede confirmação, leia com atenção. Não pressione Enter automaticamente — especialmente em comandos destrutivos.

❌

Misturar tarefas numa sessão

Feature nova + bug fix + refactor na mesma sessão gera código confuso. Uma tarefa por sessão ou use /clear entre elas.

10 — Dicas Avançadas

Recursos poderosos para aumentar produtividade

Criar slash commands customizados

# Crie .claude/commands/review-pr.md
---
description: Revisa o PR atual
---

Analise as mudanças em `git diff main...HEAD`.
Verifique:
1. Bugs óbvios
2. Problemas de segurança
3. Cobertura de testes
4. Consistência com o CLAUDE.md

Retorne um relatório estruturado.

# Usar: /review-pr

Configurar hooks automáticos

// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "npm run lint --fix"
      }]
    }],
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "echo 'Claude finalizou!'"
      }]
    }]
  }
}

🔗 MCP Servers

Conecte o Claude ao seu banco de dados, Figma, Notion, GitHub, Slack e muito mais via servidores MCP. Configure em settings.json na seção mcpServers.

🔄 Modo Autônomo

Para tarefas longas sem supervisão, use claude -p "tarefa" --no-interactive em scripts CI/CD. Configure permissões precisas antes.

📸 Análise de Imagens

Cole ou arraste screenshots, wireframes ou diagramas diretamente no chat. O Claude analisa designs e gera código correspondente.

🗂️ CLAUDE.md por Pasta

Coloque um CLAUDE.md em src/, tests/, etc. com regras específicas para aquela área do projeto.

⚡ Worktrees Git

O Claude usa worktrees para trabalhar em tarefas paralelas sem misturar branches. Útil para reviews simultâneos.

🧪 /ultrareview

Lança uma revisão multi-agente da branch atual. Execute /ultrareview ou /ultrareview <PR#> para uma análise profunda.

🌟

Fluxo de trabalho profissional recomendado

1) Inicie com /init para criar o CLAUDE.md · 2) Configure permissões no settings.json · 3) Use uma tarefa por sessão · 4) Revise com git diff antes de commitar · 5) Deixe o Claude salvar memórias úteis · 6) Use /compact em sessões longas
